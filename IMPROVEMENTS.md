# Что можно улучшить в `etch`

Документ отражает состояние ветки `master` после добавления двухфазных pipeline,
кэша эмбеддингов, tiled VAE decode, graceful shutdown и первых unit-тестов.

Правило выполнения: **один незавершённый пункт — одна отдельная ветка и один PR**.
Тесты, документация и обновление статуса пункта входят в ту же ветку. Новые
зависимости и изменения публичного CLI обсуждаются отдельно до реализации.

---

## 1. Корректность и воспроизводимость

- [ ] **Перенести все дешёвые проверки параметров до загрузки весов**
  Проверять ненулевые height/width, конечность и диапазон `flux_guidance`,
  параметры VAE tiling и расширение `--output` в начале `prepare` или в общей
  валидации CLI. Сейчас ошибки tiling обнаруживаются после денойзинга, а нулевой
  размер проходит проверку `is_multiple_of`.

## 2. Надёжность и управление ресурсами

- [ ] **Сделать запись embedding cache атомарной**
  `EmbeddingCache::set` пишет сразу в конечный safetensors-файл. Использовать
  уникальный временный файл в той же директории и atomic rename, чтобы crash или
  параллельные процессы не оставляли повреждённый кэш. Добавить тест восстановления
  после частично записанного/повреждённого файла.

- [ ] **Не скрывать ошибки чтения embedding cache**
  Оба pipeline используют `.ok().flatten()` при `cache.get`. Cache miss должен
  оставаться тихим, а повреждённый или нечитаемый существующий файл — давать
  warning с причиной и запускать пересчёт эмбеддингов.

- [ ] **Загружать конфигурацию SDXL UNet из `unet/config.json`**
  Убрать ручной `UNet2DConditionModelConfig` из LoRA-пути в `sdxl/run.rs`.
  Одинаково использовать конфигурацию diffusers с LoRA и без него, чтобы локальные
  SDXL-модели не зависели от hardcoded параметров Araminta.

- [ ] **Снизить пиковую память при применении LoRA к UNet**
  Сейчас весь UNet материализуется в CPU `HashMap`, изменяется и затем переносится
  на device. Перейти к послойной загрузке/слиянию или другому потоковому варианту,
  измерив пиковую RAM до и после. Не смешивать эту задачу с общим SSD streaming.

- [ ] **Решить судьбу WIP `feature/ssd-streaming`**
  `forward_streaming.rs` и `unet_structure.rs` ожидают именованные веса, а
  `LayerStream::next_layer()` возвращает `Vec<Tensor>`; отключённые файлы имеют
  ошибки компиляции. Либо довести эксперимент до изолированного компилируемого
  состояния с измеримой выгодой, либо закрыть его и сохранить выводы в ветке/PR.

- [ ] **Добавить проверки Ctrl-C между длительными подэтапами**
  Проверять interrupt между загрузкой крупных компонентов и между VAE-тайлами.
  Синхронные скачивание, model forward и decode одного тайла могут оставаться
  непрерываемыми до второго Ctrl-C; это ограничение документировать.

## 3. Архитектура и рефакторинг

- [ ] **Убрать неподготовленное состояние из `Pipeline`**
  Сейчас обе реализации хранят `Option<Prepared>`, а `generate(&Args)` можно
  вызвать до `prepare` или передать аргументы, несовместимые с загруженными весами.
  Сделать `prepare` возвращающим prepared pipeline, а в `generate` передавать
  только per-image request (seed/output). Убрать клонирование полного `Args` для
  каждого seed и runtime-проверки `pipeline not prepared`.

- [ ] **Не создавать большой общий abstraction layer для FLUX и SDXL**
  Общие helpers стоит выделять только там, где совпадают инварианты: валидация
  output/tiling, JSONL metadata, завершение прогресса при ошибках. Text encoding,
  scheduler, latents и model config оставить самостоятельными в каждом pipeline.

## 4. UX, CLI и диагностика

- [ ] **Добавить позицию в батче и итоговую сводку**
  Выводить `[current/total]` для каждого seed, а в конце — число успешных и
  неуспешных генераций, общее и среднее время. Прерванный батч отображать отдельно.

- [ ] **Сделать JSONL пригодным для точного воспроизведения запуска**
  Записывать эффективные `steps`, размеры и dtype вместо `null`/отсутствующих
  значений; использовать CLI-имена моделей и scheduler'ов (`dev-gguf`,
  `euler-a-karras`). Ошибка записи лога после сохранения изображения должна быть
  warning, а не завершать оставшийся батч.

- [ ] **Добавить контекст ошибок HuggingFace Hub**
  В `hub::fetch` указывать репозиторий и файл. Для 401/403 добавлять подсказку
  про `HF_TOKEN`/`huggingface-cli login`, для сетевых ошибок — понятный контекст,
  не подменяя исходную цепочку ошибки.

- [ ] **Закрыть оставшиеся silently ignored комбинации флагов**
  Предупреждать о `--quantization` с полным FLUX, `--lora-scale` без `--lora`,
  `--vae-tile-overlap` без tiling. По возможности использовать явность аргумента
  из clap вместо сравнения с default; не делать ложных warning для значения по
  умолчанию, если пользователь не передавал флаг.

- [ ] **Добавить `--prompt-file <path>` и/или `--prompt -` для stdin**
  Определить взаимоисключение с обычным `--prompt`, обработку UTF-8, пустого
  файла и ошибок чтения. Добавить CLI-тесты без загрузки модели.

- [ ] **Добавить обслуживание embedding cache**
  Команда/флаг для очистки `~/.cache/etch/embeddings/` и вывод размера/пути кэша.
  Операция удаления требует явного подтверждения пользователя и не должна
  запускаться вместе с генерацией неявно.

- [ ] **Определить политику перезаписи `--output`**
  Сейчас повторный запуск с явным output и тем же seed перезаписывает изображение.
  Либо документировать overwrite, либо добавить no-clobber по умолчанию и явный
  `--overwrite`; выбранный вариант покрыть CLI-тестами.

## 5. Производительность

- [ ] **SDXL: параллельная загрузка text encoder'ов**
  По образцу FLUX использовать scoped threads при cache-miss, сохранив режим
  последовательной загрузки для ограничения пиковой памяти. Измерить startup и
  peak RAM/VRAM; обновить семантику `--sequential-te` и предупреждения CLI.

- [ ] **FLUX: кэшировать `img_ids` в `prepare`**
  Они зависят только от height/width и не должны пересчитываться для каждого seed.
  Проверить, что per-seed state не сохраняет лишние ссылки/копии больших тензоров.

- [ ] **T5: эксперимент с усечением padding**
  Сейчас T5 всегда обрабатывает 256 токенов. Усечение может ускорить короткие
  промпты, но candle-T5 не маскирует pad-токены, поэтому embeddings и изображения
  изменятся. Реализовывать только как отдельный экспериментальный режим с новой
  версией cache key и сравнением качества/времени; не включать по умолчанию.

- [ ] **Документировать `RAYON_NUM_THREADS` для GGUF**
  Добавить в README/Troubleshooting пример настройки числа CPU-потоков и пояснение,
  когда ограничение потоков снижает нагрузку и потребление памяти.

## 6. Тестирование и CI

- [ ] **Добавить unit-тесты преобразований LoRA**
  Покрыть `te_lora_base_to_weight_key`, `ldm_lora_base_to_unet_key`,
  `greedy_tokenize`, alpha/rank scaling, отсутствие совпадений и смешанные/неполные
  ключи. Проверять не только успешные примеры, но и malformed input.

- [ ] **Добавить integration smoke-test запуска**
  `--cpu --n-steps 1` не удешевляет загрузку модели, поэтому полный model smoke
  запускать вручную или в scheduled CI с HF cache, а не на каждый PR. Быстрые
  CLI integration-тесты должны проверять validation и dispatch без скачивания весов.

- [ ] **Проверять Metal-сборку в CI**
  Добавить macOS job хотя бы с `cargo check --features metal`; по возможности
  запускать clippy с `-D warnings`. Основной Linux job оставить быстрым CPU-only.

## 7. Документация и мелкие улучшения

- [ ] **Добавить doc-комментарии для `apply_lora` / `apply_te_lora`**
  Описать поддерживаемые форматы, возвращаемые коллекции, счётчик применённых
  слоёв, поведение при unmatched keys и отсутствие runtime LoRA после merge.

- [ ] **Добавить ссылки на источники констант scheduler'ов**
  Пояснить `BETA_START=0.00085`, `BETA_END=0.012`, `TRAIN_STEPS=1000`,
  `STEPS_OFFSET=1` и `RHO=7` ссылками на diffusers/Karras paper.

- [ ] **Согласовать размер SDXL по умолчанию**
  Код использует 768×1024, тогда как часть документации может намекать на
  1024×1024. Либо сменить default как отдельное поведенческое изменение, либо
  явно задокументировать причину текущего разрешения.

- [ ] **Добавить README для разработчиков**
  Описать `cargo fmt`, `cargo test`, `cargo clippy --features metal`, CPU-only CI,
  запуск model smoke-test и процесс добавления новой модели/pipeline.

## Уже реализовано

- [x] **Однозначные и полные ключи embedding cache** — ветка `fix/cache-key-unambiguous`.
  `CacheKey::from_parts` кодирует части с длинами и версией формата (`v2`), так что
  разные последовательности частей не могут дать один вход SHA-256. В ключ SDXL
  добавлен путь `--local-model`, а для LoRA — SHA-256 содержимого файла и scale.
  Regression-тесты: разбиения частей, пустые части, стабильность ключа, смена
  содержимого LoRA. Записи старого формата не переиспользуются (промах кэша при
  первом запуске, старые файлы можно удалить вручную).

- [x] **Seed для GGUF и ограничения CPU** — PR #35.
  У `Pipeline` появился `noise_device()`: `main.rs` сидит устройство, которое
  фактически создаёт шум (для FLUX GGUF — CPU, а не GPU). Проверено, что в
  candle 0.11 `Device::set_seed` для CPU завершается ошибкой (`cannot seed the
  CPU rng`), то есть CPU-запуски по сути невоспроизводимы. При шуме на CPU
  выводится одноразовое предупреждение; в README добавлена явная заметка о
  воспроизводимости.

- [x] **Нормализация tiled VAE decode** — PR #34.
  `tiled_decode` накапливает `weight_sum` и делит итог на него; рампы feather-масок
  переведены на `(x+1)/(overlap+1)`, чтобы соседние тайлы никогда не давали нулевую
  сумму весов на шве. Тест с константным latent и identity decoder фиксирует
  константность выхода во всех пикселях, включая края и углы.

- [x] **Безопасный append в `log.jsonl`** — PR #24.
  Строка целиком форматируется и пишется одним `write_all` в append-mode файл.

- [x] **Graceful shutdown по Ctrl+C** — PR #25.
  Первое нажатие останавливает на границе шага/seed с кодом 130, второе — сразу.

- [x] **Запрет одновременных `metal + cuda`** — PR #26.
  `compile_error!` в `src/device.rs` исключает неоднозначный выбор backend.

- [x] **Предупреждения об основных флагах не своей модели**
  Реализованы `ignored_flag_warnings` и unit-тесты в `src/cli.rs`.

- [x] **Валидация `--n-steps`**
  Значение 0 отклоняется до загрузки модели; добавлена верхняя граница 1000.

- [x] **Лимит `--seed-range`**
  Диапазон ограничен 100000 seed'ами; overflow и oversized input покрыты тестами.

- [x] **Быстрое PNG-кодирование**
  `PngEncoder` использует `CompressionType::Fast` и `FilterType::Adaptive`.

- [x] **Unit-тесты Karras scheduler'ов**
  Проверяются границы, монотонность sigmas, диапазон timesteps и `n_steps=1`.

- [x] **Базовые unit-тесты CLI и сохранения изображений**
  На момент обновления документа `cargo test` выполняет 18 тестов успешно.
