## ⚡ Производительность

- [ ] **SDXL: параллельная загрузка text encoder'ов**  
  `sdxl/run.rs` грузит и кодирует CLIP-1 и CLIP-2 последовательно; во FLUX они уже параллелятся через `std::thread::scope`. Экономия ~2–5 с на старте при cache-miss. Обратная сторона — выше пиковая память (оба энкодера резидентны одновременно), нужен флаг по образцу `--sequential-te`.

- [ ] **PNG-кодирование с быстрым сжатием**  
  `image.rs`: `save_buffer` использует дефолтный уровень PNG-сжатия (~0.5–1.5 с на 1360×768). `PngEncoder` с `CompressionType::Fast` даёт ~3–5× быстрее при файлах на 10–20% больше. Флаг `--png-fast` или дефолт. Заметно в батчах.

- [ ] **FLUX: кэшировать `img_ids` в `prepare`**  
  `flux/run.rs`: `State::new` пересчитывает `img_ids` на каждый сид, хотя они зависят только от height/width. Посчитать один раз в `prepare`. Экономия малая, но бесплатная.

- [ ] **T5: усечение паддинга до реальной длины промпта** (экспериментально)  
  `flux/run.rs`: `tokens.resize(256, 0)` — T5-XXL всегда считает attention по 256 токенам (O(n²)). Усечение ускорило бы кодирование коротких промптов, **но** candle-T5 не маскирует pad-токены, поэтому эмбеддинги изменятся (и инвалидируют кэш). Только за флагом.

- [ ] **Документировать `RAYON_NUM_THREADS` для GGUF**  
  GGUF DiT считается на CPU через rayon; число потоков нигде не упомянуто. Строка в README/Troubleshooting.

## 🎨 UX и CLI

- [ ] **Предупреждения о флагах не своей модели**  
  Молча игнорируются: `--lora`, `--guidance-scale`, `--uncond-prompt`, `--scheduler`, `--clip-skip`, `--local-model` при FLUX; `--flux-guidance`, `--gguf`, `--quantization`, `--sequential-te` при SDXL; `--uncond-prompt` при `--guidance-scale <= 1` (CFG выключен). Нужны warning'и вида «--lora is SDXL-only, ignoring».

- [ ] **Валидация `--n-steps`**  
  `--n-steps 0` → паника деления на ноль в `schedulers.rs` (`TRAIN_STEPS / n_steps`). Нужен `ensure!(n_steps >= 1)` и разумная верхняя граница от опечаток.

- [ ] **Лимит `--seed-range`**  
  `cli.rs`: `parse_seed_range` коллектит весь диапазон в `Vec<u64>` — `0-100000000` это ~800 МБ и фактический OOM. Лимит (например, 100k) с внятной ошибкой или ленивая итерация.

- [ ] **Воспроизводимость `--seed` в GGUF-режиме**  
  Шум генерится на `flux_device` (CPU для GGUF), а `device.set_seed` в `main.rs` вызывается для Metal. Вызывать `set_seed` на `flux_device` в `generate_flux`; если CPU-PRNG в candle не seed'ится — честно предупреждать в логе.

- [ ] **Ctrl-C во время долгих фаз без чекпоинтов**  
  Продолжение PR #25: флаг не проверяется во время загрузок весов в `prepare` и между тайлами в `tiled_decode`. Добавить проверки — первое нажатие станет отзывчивее.

- [ ] **Подсказка про HF_TOKEN для gated-моделей**  
  При 401/403 от Hub (`hub.rs::fetch`) добавлять в ошибку «run `huggingface-cli login` or set HF_TOKEN» — сейчас первый запуск FLUX.1-dev без токена падает непонятно.

- [ ] **Прогресс батча: позиция и сводка**  
  В логе `--- Seed: 42 (range) ---` без позиции; добавить `[3/101]` и итоговую сводку в конце (N картинок, общее/среднее время).

- [ ] **`--prompt-file <path>` (или `--prompt -` для stdin)**  
  Длинные промпты с кавычками и переводами строк из шелла — боль.

- [ ] **Обслуживание кэша эмбеддингов**  
  `~/.cache/etch/embeddings/` растёт неограниченно (~1–3 МБ на промпт). Флаг `--clear-embedding-cache` и/или упоминание в README.

- [ ] **Ранняя валидация расширения `--output`**  
  Поддерживаются только png/jpeg; `.webp`/`.bmp` падают глубоко в image crate. Проверять сразу с понятным сообщением.

## 🛡 Надёжность

- [x] **Безопасный `append` в `log.jsonl`** — сделано в PR #24.  
  Строка целиком форматируется и пишется одним `write_all` в файл с `append(true)`: `O_APPEND` (POSIX) / `FILE_APPEND_DATA` (Windows) гарантируют атомарность. Явная блокировка (`fd-lock`/`fs2`) не понадобилась.

- [x] **Graceful shutdown по `Ctrl+C`** — сделано в PR #25.  
  Модуль `src/signals.rs` (крейт `ctrlc`): первое нажатие останавливает генерацию на границе шага денойзинга и между сидами (код выхода 130, прерванный прогон не логируется как failed), второе — немедленный выход.

## ✅ Недавние улучшения (этот цикл)

- PR #21 — **candle 0.10.2 → 0.11.0**: Metal concurrent dispatch, ускоренный gemv, фиксы SDPA/RMSNorm/readback-race, безопасный GGUF-лоадер.
- PR #22 — **reuse весов в батч-режиме**: `Pipeline` разделён на `prepare` (загрузка один раз) / `generate` (на каждый сид); заодно фикс BF16→F32 каста латента перед VAE decode в FLUX.
- PR #23 — **ключ кэша эмбеддингов**: добавлены режим CFG (`cfg1`/`cfg2`) и dtype — раньше прогон с `--guidance-scale 1.0` и `7.5` на одном промпте делили один кэш (падение на `chunk(2, 0)`).
- PR #27 — **кэш feather-масок в tiled VAE decode**: маска зависит только от `(out_h, out_w, feather-флаги)`, внутренние тайлы переиспользуют одну вместо пересчёта и re-upload на каждый тайл.
